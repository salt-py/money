# Product

User profiles this tool is designed for (or could reasonably grow to
serve) — one file per profile. Used to reason about what to build next:
a proposed feature should be traceable to at least one real profile's
actual need, not added because it seemed neat.

## Conventions

- **Filename**: `firstname(s).md`, lowercase, hyphenated for a pair
  (e.g. `jess-and-alex.md`).
- Each file has: a name, a one-paragraph "why they use this tool," and a
  list of useful features split into what's already built (✅) and what's
  proposed but not yet built (🔲).
- A profile is grounded in a genuine, distinct need — not a feature
  wearing a name. If two profiles would list nearly identical feature
  sets, they're the same profile.
- When a 🔲 feature gets built, flip it to ✅ here as part of that work,
  and consider whether it's worth its own entry in `tickets/`.
